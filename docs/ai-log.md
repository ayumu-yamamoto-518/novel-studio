# AIログ

AIの出力が間違っていた場合や、人が直した場合の記録。

- 実際に起きたことだけを書く。
- 人が「記録して」と言ったときに下書きを作り、人が確認してから保存する。

## テンプレート

新しい記録は、この下に新しい順で追加する。

```markdown
### YYYY-MM-DD タイトル

- **何が起きたか**:
- **どう気づいたか**:
- **どう直したか**:
- **学び**:
```

## 記録

### 2026-11-01 「Read(.env) の拒否は Bash の cat を止めない」と記録したが、公式ドキュメントと食い違っていた

- **何が起きたか**: 権限設定の `Read(./.env)` について、「Bash の `cat` は止めない」と作業メモと報告に書いた。実際に試したものではなかった。公式ドキュメントでは、Read の拒否ルールは `cat`・`head`・`tail`・`sed`・`tee` とリダイレクト先にも適用され、止まらないのは、ファイル名を指定しない `grep -r` や、Python/Node のスクリプトがファイルを直接開く場合と書かれている。
- **どう気づいたか**: docs/ai-log.md に限界として記録する際に、根拠を公式ドキュメント(https://code.claude.com/docs/en/permissions)で確認し直した。このセッションでも、`cat .env` を含むコマンドは拒否され、`.env` を Write で作ることも拒否された(`cat` 単独では確認できていない)。
- **どう直したか**: 記録を正しい限界(`grep -r` とスクリプト経由は止まらない)に直した。技術的には塞がず、人の許可と、`.env` に秘密情報を置かない運用で補う。
- **学び**: 権限ルールの効く範囲は、記憶や推測で書かず、公式ドキュメントの記述と実際の拒否で確かめる。

### 2026-11-01 git の許可ルールが、任意ファイルの書き込み・読み取りを確認なしで通した

- **何が起きたか**: `.claude/settings.json` の allow に `git diff *`・`git log *`・`git show *` を「読み取り専用」として入れた。しかし `git diff` は `--output=<ファイル>` で任意のパスに書き込め、`--no-index` で範囲外のファイルを読めた。
- **確認できたこと**: 上の2点は、レビュアーが実際にコマンドを実行して確認した。ask に入れた旧パターン `git diff --no-index *` は、`--no-index` の前に別のオプションが入ると一致せず、`git diff --stat --no-index a b` が確認なしで実行されることを、このセッションで実際に確かめた。
- **どう気づいたか**: 全ブランチのレビュー(別コンテキストのレビュアー)が指摘した。Claude Code は名前から読み取り専用と思い込み、実行して確かめていなかった。
- **どう直したか**: ask に `Bash(git diff --no-index *)` と `Bash(git * --output*)` を追加し(6524f1d)、のちに `--no-index` のパターンを位置を問わない `Bash(git diff *--no-index*)` に直した(bfeeb14)。このプロジェクトではどちらのオプションも使わないため、最終的に2つとも ask から deny に移した(b8d0545)。
- **直したあとに確認できたこと**: 新しい場所(~/Developer/novel-studio)で、deny に移したあとに `git diff --stat --no-index .nvmrc .prettierrc` を単独で実行すると、拒否された。以前は確認なしで実行された同じコマンドなので、`Bash(git diff *--no-index*)` は `--no-index` の前にオプションがあっても効いている。ask のときに確認が出なかった理由(権限モードで省略されていたのか、ルールが効いていなかったのか)は、deny にしたため切り分けていない。同じく、`git diff --output=/private/tmp/diffout-test.txt .nvmrc` を単独で実行すると拒否され、出力先のファイルは作られなかった。`Bash(git * --output*)` も効いている。
- **まだ確認していないこと**: deny に移したあとのコミットコマンドが、メッセージ本文に `--no-index` と `--output` を含んでいたために拒否された。パターンはコマンド全体の文字列に一致するようなので、本文に書いただけでも拒否されると考えられるが、どちらのパターンに一致したかは切り分けていない。コミットメッセージはファイル経由(`git commit -F`)で渡して回避した。
- **学び**: 「読み取り系」と名前だけで決めず、オプションの組み合わせを実際に試す。ルールを直したあとは、そのコマンドが止まることまで確かめる。

### 2026-11-01 CLAUDE.md が、指定した本体ではなく依頼文の全文になっていた

- **何が起きたか**: CLAUDE.md は「依頼文の `~~~markdown` ブロックの中身」だけで作る指定だった。しかしコミットされたファイルは依頼文の全文(109行。「使い方」「やること A〜I」を含む)で、ルール本体はコードフェンスの中に入っていた。コミットメッセージには「依頼文のとおり作成」と書いていた。なぜ全文になったかは分かっていない。
- **どう気づいたか**: 全ブランチのレビューで、レビュアーが実ファイルを依頼のブロックと突き合わせて指摘した。Claude Code は作成後に、実ファイルを読み返していなかった。`npm run check` には CLAUDE.md の中身を検査するものがない。
- **どう直したか**: フェンスの内側の35行だけにした(6524f1d)。先頭が `# novel-studio` で `~~~` が無いことを、シェルで確認した。
- **学び**: 毎セッション読み込まれるファイルは、書いたあとに実ファイルを読み返す。自動検査に載らないファイルは、人か別の目で確認する。

### 2026-11-01 `msw init --save` が package.json を Prettier の書式から外した

- **何が起きたか**: `npx msw init public/ --save` が `package.json` に MSW の設定を追記し、Prettier の書式から外れた。
- **どう気づいたか**: 設定ファイルをまとめて確認したとき、`npm run format:check` が `package.json` を警告した。`npm run check` には `format:check` が含まれていないため、`check` と CI では検出されない。
- **どう直したか**: Prettier で整えた(c7e7d40)。
- **学び**: 生成コマンドが書き換えたファイルは、整形を確認する。`format:check` が `check` に含まれていないことに注意する。

### 2026-11-01 MSW のオプション名を記憶で書き、導入した版で変わっていた

- **何が起きたか**: MSW の未処理リクエストの扱いを、記憶にある v2 のオプション名 `onUnhandledRequest` で書いた。導入された 3.0.3 では `onUnhandledFrame` に変わっていた。「記憶に頼らず公式ドキュメントで確認する」というルールに反していた(確認した公式の Quick Start には、このオプションが載っていなかった)。
- **どう気づいたか**: `npm run check` の型検査が TS2353(未知のプロパティ)で失敗した。
- **どう直したか**: `node_modules/msw` の型定義(`shared-options.d.ts`)を読み、`onUnhandledFrame` に変えた(61b8055)。
- **学び**: 版が新しいライブラリは、導入された版の型定義を読んで確かめる。strict な型検査が名前の食い違いを検出してくれた。

### 2026-11-01 Testing Library の自動クリーンアップが効かず、テストが失敗した

- **何が起きたか**: Testing Library の自動クリーンアップが効く前提でテストを書いた。しかし Vitest は globals が無効なため効かず、前のテストの DOM が残って「ボタンが複数見つかる」で失敗した。
- **どう気づいたか**: ボタンの表示テストを追加したとき、`npm run check` のテストが失敗した(`Found multiple elements with the role "button"`)。
- **どう直したか**: `src/test/setup.ts` に `afterEach(cleanup)` を明示した(1acea75)。
- **学び**: Vitest で globals を無効にしているときは、クリーンアップを自分で書く。

### 2026-11-01 基本設定の ESLint では、eslint-disable コメントで any を隠せた

- **何が起きたか**: `typescript-eslint` の recommended と react-hooks だけの設定では、`// eslint-disable-next-line @typescript-eslint/no-explicit-any` を付けると、`any` が検出されず終了コード 0 になった。
- **どう気づいたか**: 禁止ルールを入れる前に、一時ファイルでわざと試した。`any` 単体と `@ts-ignore` は検出された。
- **どう直したか**: `linterOptions` に `noInlineConfig: true` と `reportUnusedDisableDirectives: 'error'` を入れた(7e3c669)。lint は `--max-warnings 0` なので、「効果なし」の警告も失敗になる。最終状態でも、`eslint-disable` に隠した `any` が lint で失敗することを再確認した。
- **学び**: 禁止したいことは、「実際にできてしまう」ことを先に試してから塞ぐ。

### 2026-11-01 Vite の雛形が ESLint ではなく oxlint で、TypeScript は 7.x だった

- **何が起きたか**: 計画では、雛形に ESLint の設定が入っている前提で「拡張する」としていた。実際の雛形(create-vite v9.3.3)は oxlint で、TypeScript は `~7.0.2` だった。typescript-eslint 8.72.1 の対応範囲は `typescript <6.1.0` までで、7.x では使えなかった。
- **どう気づいたか**: 雛形を生成し、`package.json` と tsconfig を読んだ。計画を立てた時点では、雛形の中身を確認していなかった。
- **どう直したか**: oxlint を外して ESLint に置き換え、TypeScript を `~6.0.3` に固定した(3f52ec8)。
- **学び**: 雛形の中身は、計画時の記憶ではなく、生成して確認してから前提にする。
